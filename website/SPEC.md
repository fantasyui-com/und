## Complete feature inventory

1. **Initialize a store — `path(location)`**: creates missing ordinary directories; await it before all other operations. Relative paths use the Node process working directory. Invalid paths and symlink components reject. Factory creation itself performs no I/O; factory configuration options are not implemented. Browser samples select a server-owned location automatically, not a user-entered host path.
2. **Save a document — `put(data)`**: JSON object with valid `id` produces a new file and returns a JSON copy with numeric `rev` and fresh UUID-v4 `uid`. Input and earlier revisions are unchanged. Omitted/null/zero rev observes the latest; a positive valid rev intentionally names the base, even if stale. JSON serialization may omit unsupported property values under normal JSON behavior; reject serialization/identity failures. No upsert API is implied.
3. **Read the selected document — `get(id)`**: returns the highest numeric revision and then greatest complete filename for a tie, or null for no revision. Corrupt selected JSON and identity mismatch reject instead of silently showing old content. Winner selection is not conflict merging, notification or a business rule.
4. **Check record presence — `has(id)`**: checks an ordinary record directory; a present but empty record can have `has=true`, `get=null`, `rev=0`. It is not a document-integrity check. Root-level ordinary files are not records.
5. **List record IDs — `all()`**: returns record-directory IDs in deterministic lexical order; it does not return documents or all revisions. Explain a short `all` then `get` loop without suggesting an atomic multi-record snapshot. Unrelated root files are preserved and excluded.
6. **Inspect latest revision number — `rev(id)`**: reads revision filenames and returns the maximum or zero. It does not validate JSON bodies or count revisions/conflicts.
7. **Explicitly prune older groups — `clean(depth=1)`**: retains every file in the highest N distinct revision groups and returns absolute paths removed. Validate positive safe-integer depth; validate all documents before deletion. Same-revision conflicts in retained groups all survive. Repeated successful cleanup returns an empty array. Stop concurrent writes and back up wanted history; unlink failures can leave partial cleanup. There is no record-delete method.
8. **Retain independent writes**: new files prevent one ordinary same-base write replacing another; show both returned saved values. UUIDs and path validation do not prove OS isolation or universal durability. There is no transaction, merge, replication or synchronization facility.
9. **Deterministic ordering**: numeric revision ordering and locale-independent full-filename tie-break are explicit 3.0 choices. UUID appearance is not chronology, and winner changes are not merge success.
10. **Validate identities and errors**: ID is a nonempty single path component; reject dot/dot-dot, slash/backslash/NUL and unpaired UTF-16 surrogates. Valid Unicode stays unnormalized. I/O errors remain errors, not absence. Explain relevant error near the failing input; Docs retain exact limitations and technical detail.
11. **Use the direct CLI**: `und --help`, `und --version`, `und clean [db] [-d|--depth N]`. Default database is the current directory, so examples always pass a temporary path explicitly. `--depth=N` and a `--` operand separator are accepted. No arguments print help; clean requires an existing database directory and never creates one; successful clean is silent; invalid syntax and filesystem failures use stderr/nonzero exit. `--no-tests` is retired. The site adds no prerequisite to this contract.
12. **Run dependency-free local code**: supported package entry is CommonJS index.js; Node >=22 is declared, existing migration execution evidence is Node 26.11.1. No third-party package installation is needed. ESM sketches, upsert, history/conflict enumeration, views, deletion, replication and synchronization are not supported. Do not call this secure, distributed, production-ready or SOTA on the strength of this inventory.

## Minimal local reactive helper contract

website/public/state.mjs exports Signal(initial) with get/set/subscribe, EventEmitter() with emit/subscribe, SignalBinder(element,signal) returning unsubscribe, and DisposableScope() with use(cleanup)/dispose(). Subscriptions return an unsubscribe function; they do not emit an initial value. SignalBinder explicitly renders the initial value and subsequent values as textContent (an optional custom renderer may be supported). Signal updates queued by a listener commit only after all listeners of the current revision have been notified, so callback value and get agree. Event delivery uses ordered snapshots; removing a listener during emission affects later emissions. Reentrant emissions queue. DisposableScope is synchronous, closes admission before cleanup, attempts all cleanup even after an exception, reports errors, is idempotent, and immediately disposes late additions. Async network ownership uses a current revision plus disposal flag; abort alone cannot authorize a stale result. These are website-local helpers, not a general framework.
