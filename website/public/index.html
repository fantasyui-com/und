SMALL LIBRARY. VISIBLE REVISIONS.

Every edit gets
its own revision.

Save JSON. Keep the earlier writes. Understand exactly what comes back.

und is a small Node.js CommonJS document store. Each record has a directory; each save adds a new JSON file. You choose when to prune older revision groups.

Try in PlaygroundStart Tutorial

The Playground uses disposable local samples. No application database is opened.

A record becomes a small folder

sample/
└── profile/
    ├── 1-<first UUID>.json
    └── 2-<new UUID>.json

// First saved value
{ "id": "profile", "name": "Mira",
  "rev": 1, "uid": "…" }

// A later saved value
{ "id": "profile", "name": "Mira Chen",
  "rev": 2, "uid": "…" }

Earlier files stay until an explicit clean(). A UUID identifies a write; it is not a timestamp.

Is und right for this job?

Use it when a small local filesystem JSON store and explicit revisions fit your application. This is not a browser database: this website sends local requests to Node, which calls the installed library.

No transactions, automatic merge, conflict notification, replication or synchronization. No claim of power-loss durability, network-filesystem safety or hostile-process isolation. Stop writers before cleanup. If you need those guarantees, this API does not provide them.

WHAT YOU CAN RELY ON

Features

Seven methods, one direct CLI, and explicit boundaries. Follow each capability to its contract and a runnable lesson.

01 · Initialize a store

path(location) creates missing ordinary directories. Await it first; relative paths use the process directory. Symlink components reject. Factory options are not implemented.

Initialization docs · Tutorial setup

02 · Save a document

put(data) returns a copied JSON object with a numeric revision and fresh UUID. Input and earlier files stay unchanged. A positive revision explicitly chooses a base, including a stale one.

Save docs · Profile lesson

03 · Read a value

get(id) selects the highest numeric revision, then greatest filename for a tie. Missing data returns null; corrupt selected data rejects, with no fallback.

Read docs · Missing-data example

04 · Check presence

has(id) checks an ordinary record directory. It is not an integrity check: an empty directory can have has=true, get=null, rev=0.

Presence docs · Inspect a record

05 · List record IDs

all() returns IDs in deterministic lexical order. It excludes unrelated ordinary root files. An all then get loop is not an atomic snapshot.

List docs · List example

06 · Inspect a revision

rev(id) returns the maximum revision or zero for absent/empty data. It reads filenames, not JSON bodies, and does not count files or conflicts.

Revision docs · Inspect a record

07 · Prune older groups

clean(depth) keeps every file in the highest N distinct revision groups. It validates all documents first and returns removed paths. There is no record-delete method.

Cleanup docs · Depth 2/1 example

08 · Retain independent writes

Two edits from one base produce distinct files at the same next revision. Both survive. Selection does not merge fields or notify you about a conflict.

Write semantics · Try two edits

09 · Predictable ordering

Revision 10 sorts after 9. Ties use the greatest full filename under locale-independent JavaScript string comparison. UUID order does not express chronology.

Ordering docs · Selection example

10 · Validate identities

IDs are nonempty single path components. Invalid IDs, revisions and corrupt data reject. Valid Unicode is kept without normalization. I/O failures remain errors.

Error docs · Handled error

11 · Use the direct CLI

Help, version and explicit cleanup work without this website. Cleanup is silent on success. Invalid syntax or I/O failure writes to stderr and exits nonzero.

CLI docs · Safe CLI example

12 · Run local, dependency-free code

The library uses Node built-ins. No package installation is needed in this checkout. The unfinished ESM sketches do not add APIs; upsert, views and history enumeration are unsupported.

Local usage · Complete program

Revisions and publication

A file is profile/10-<UUID-v4>.json. Numeric revision comes first; the greatest complete filename breaks ties. A positive stale base intentionally branches. Choosing the winner does not merge the other write.

Each operation captures one selected database before awaiting. A later path() cannot redirect an already admitted operation. Concurrent configuration completion is not a queue.

A complete revision is published exclusively. A prepublication failure preserves prior readable data; internal staging is excluded from records. Once publication commits, staging cleanup failure does not turn it into a failed save. A lost response leaves the caller uncertain: read to reconcile, never blindly replay.

No fsync/power-loss guarantee, cleanup/write transaction, hostile-filesystem protection, replication or network-filesystem guarantee.

IDs, missing data and errors

An ID is a nonempty single path component. Reject ., .., slash, backslash, NUL and unpaired UTF-16 surrogates. Valid Unicode is preserved without normalization. Filesystem component-length limits still apply; an overlong ID produces an I/O error rather than a saved document.

get('missing') → null, rev('missing') → 0 and has('missing') → false describe absence. I/O or validation errors reject instead. Catch them and keep the user's unsaved draft.

The Playground rejects invalid JSON, unknown operations, arbitrary paths, foreign origins and bodies over 256 KiB. It offers no import, shell or code execution. These local checks and UUIDs are not an OS trust boundary.

Direct CLI

node cli.js --help
node cli.js --version
node cli.js clean /explicit/sample/path --depth 2
# Installed CLI syntax: und clean [db] [-d|--depth N]

No arguments prints help. Omitted database means the current working directory; examples always pass an owned temporary path. Depth defaults to 1; --depth=N is also accepted, and -- precedes a path that begins with a dash. The database directory must already exist: a missing path fails and nothing is created. Successful cleanup is silent. Unknown/repeated options, extra operands and invalid depths fail before storage access with stderr and nonzero exit status. --no-tests is retired.

YOUR FIRST RECORD, END TO END

Tutorial

From this checkout run node website/examples/tutorial.cjs. No install is needed. It uses a temporary directory and removes it in finally.

  1. Initialize. Await path. Empty list is [], missing read is null, revision is 0. Try List, Read and Inspect revision.
  2. Create and update. First save returns revision 1 plus UID. Spread that return into an edited object; the next save returns revision 2. Save a document.
  3. Inspect and reopen. List returns the ID; presence is true; a second initialized instance reads the same saved value.
  4. Keep two edits. Both saves from one base return the same next revision with distinct UIDs. get chooses one; it does not combine their fields. Try the same-base lesson.
  5. Make a deliberate application choice. The example combines name and color itself and saves from the current selected document. That policy belongs to the application.
  6. Handle failure and clean. Invalid ID rejects and is caught. With writers stopped, depth 1 removes old groups. Repeating clean returns []. Try cleanup.
